## Identity_Users schema drift + critical RowVersion bug fix
User manually created the REAL `Identity_Users` table in their own SQL Server instance (db `Sugentra_ERP`) and it differs from the original DDL script: added `PhoneNumber`, `EmployeeId` (NIP), `ProfilePictureUrl`, `LastLoginAt`, `FailedLoginAttempts`, `LockoutEnd` — and **removed the `RowVersion` column entirely**. The script file `0001_Identity_Users.sql` was updated to match (also `CreatedAt` default changed to `GETDATE()` from `SYSUTCDATETIME()` — cosmetic, not chased elsewhere yet).
- **Critical bug found & fixed globally:** `Shared/Persistence/Repository<TEntity>.ResolveWritableColumns()` was including `RowVersion` in every entity's generated INSERT/UPDATE column list. **SQL Server's `ROWVERSION`/`timestamp` type can NEVER be explicitly written** (`INSERT`/`UPDATE` on it throws "Cannot insert an explicit value into a timestamp column") — this would have broken `AddAsync`/`UpdateAsync` for EVERY entity still carrying a real `RowVersion` column in the DB (Role, Permission, UserRole, RolePermission, UserPermission, UserRefreshToken all still had it at this point). Fixed by excluding `nameof(BaseAuditableEntity.RowVersion)` alongside `Id` in `ResolveWritableColumns()` (this rule became moot once `RowVersion` was later removed from the convention entirely, see [../plan.md](../plan.md)'s "Script consolidation" note).
- **`User` entity updated** (`Modules/Identity/Entities/User.cs`) to match the real table 1:1: added `PhoneNumber`, `EmployeeId`, `ProfilePictureUrl` (all `string?`), `LastLoginAt` (`DateTime?`), `FailedLoginAttempts` (`int`), `LockoutEnd` (`DateTime?`).
- **Dtos updated** (`Modules/Identity/Dtos/UserDtos.cs`): `CreateUserRequest` gained optional `PhoneNumber`/`EmployeeId`; `UpdateUserRequest` gained optional `PhoneNumber`/`EmployeeId`/`ProfilePictureUrl`; `UserResponse` gained `PhoneNumber`/`EmployeeId`/`ProfilePictureUrl`/`LastLoginAt`. `FailedLoginAttempts`/`LockoutEnd` deliberately NOT exposed via any DTO yet at this point (actual lockout enforcement was a later session, see below). `UserListItemDto` deliberately left unchanged/lean (list endpoint doesn't need every column).
- **`UserUseCase` updated**: `CreateAsync` maps `PhoneNumber`/`EmployeeId` into the new `User`; `UpdateAsync` maps `PhoneNumber`/`EmployeeId`/`ProfilePictureUrl`; `ToResponse` includes the new fields.
- **Migrator's `SeedSuperAdmin()` raw INSERT untouched** — it explicitly lists only `(Username, Email, PasswordHash, FullName, IsActive, CreatedBy)`, and all new columns are nullable/defaulted, so no changes needed there.

## Account lockout enforcement
Uses the existing-but-previously-unused `User.FailedLoginAttempts`/`LockoutEnd` columns. No schema change needed.
